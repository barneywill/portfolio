The usual reason for this problem is that multiple open source jars are used in the project, and each open source jar has its own log implementation method, such as slf+log4j, slf+logback, etc., where slf is an abstract interface with many implementations, but there can only be one in the project. The solution has been prompted in the exception:

Either remove Logback or the competing implementation (class org.slf4j.impl.Log4jLoggerFactory loaded from file:/usr/local/tomcat/webapps/app/WEB-INF/lib/slf4j-log4j12-1.7.25.jar).

You need to remove one between logback and slf-log4j. Spring boot uses logback, so you can remove slf-log4j;

pass

mvn dependency:tree

You can see that those jars depend on slf-log4j, and then modify the pom to exclude it.

        <dependency>
            <groupId>org.apache.hadoop</groupId>
            <artifactId>hadoop-client</artifactId>
            <version>2.6.5</version>
            <exclusions>
                <exclusion>
                    <groupId>org.slf4j</groupId>
                    <artifactId>slf4j-log4j12</artifactId>
                </exclusion>
            </exclusions>
        </dependency>

Then pack it;
