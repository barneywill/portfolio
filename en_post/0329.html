question

The latest version of Drill is 1.14. Starting from 1.13, the version of Drill that supports Hive has been upgraded to 2.3.2. For details, please see the release notes of 1.13.

  • The Hive client for Drill is updated to version 2.3.2. With the update, Drill supports queries on transactional (ACID) and non-transactional Hive bucketed ORC tables. The updated libraries are backward compatible with earlier versions of the Hive server and metastore. (DRILL-5978)

Forcibly using Drill 1.14 to connect to Hive 2.1.1 will cause problems due to changes in the metastore thrift interface. Specifically, the show tables are empty, and the specific error is as follows:

compile

So I tried to recompile Drill1.14, dropped the dependent Hive version to 2.1.1, and downloaded the code

http://mirror.bit.edu.cn/apache/drill/drill-1.14.0/apache-drill-1.14.0-src.tar.gz

 

POM

Modify Hive version in pom

<hive.version>2.3.2</hive.version>

Modify to <Hive.version>2.1.1</Hive.version>

After recompiling and packaging, it was found that the problem remained. After checking, it was found that after the modified version, only three Hive-related jars under jars/3rdparty were changed from 2.3.2 to 2.1.1.

hive-contrib-2.1.1.jar
hive-hbase-handler-2.1.1.jar
hive-metastore-2.1.1.jar

The jar that reported the error is drill-Hive-exec-shaded-1.14.0.jar. This jar package contains Hive-exec and its dependencies.

        <artifactId>maven-shade-plugin</artifactId>

        <configuration>

          <artifactSet>

            <includes>

              <include>org.apache.hive:hive-exec</include>

And the configured Hive.version is not used

    <dependency>

      <groupId>org.apache.hive</groupId>

      <artifactId>hive-exec</artifactId>

      <scope>compile</scope>

As a result, the Hive-exec included in the jar package is version 2.3.2, and the Hive.version configuration is added.

    <dependency>

      <groupId>org.apache.hive</groupId>

      <artifactId>hive-exec</artifactId>

      <version>${hive.version}</version>

      <scope>compile</scope>

After packaging again, the problem disappears and the show tables are normal;

Hadoop Location

The official documentation explains as follows:

Apache Drill users must tell Drill-on-YARN the location of your Hadoop install. Set the HADOOP_HOME environment variable in $DRILL_SITE/drillenv.sh to point to your Hadoop installation:

export HADOOP_HOME= /path/to/hadoop-home

But there are still problems after configuration:

1) Report an error

Diagnostics: File file:/user/drill/site.tar.gz does not exist
java.io.FileNotFoundException: File file:/user/drill/site.tar.gz does not exist

Need to add link

ln -s $HADOOP_HOME/etc/hadoop/core-site.xml $DRILL_SITE/core-site.xml

2) During the actual query, an error will be reported and hdfs_name cannot be found. You need to add a link.

ln -s $HADOOP_HOME/etc/hadoop/hdfs-site.xml $DRILL_SITE/hdfs-site.xml
