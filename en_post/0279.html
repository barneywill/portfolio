View the real-time memory and CPU resources occupied by each application in YARN

📅 January 10, 2019
📖 2 min read
👁️ 14798 views

Application details page in YARN

http://resourcemanager/cluster/app/$applicationId

Or through the application command

yarn application - status $applicationId

You can only see the resource * time statistics occupied by the application since it was started, such as:

Aggregate Resource Allocation : 3962853 MB-seconds, 1466 vcore-seconds

The current real-time resource usage of this application cannot be found anywhere, such as how much memory and cores are currently occupied. After following the YARN code, I found that there is actually this statistic:

org.apache.hadoop.yarn.api.records.ApplicationResourceUsageReport

  public static ApplicationResourceUsageReport newInstance(
      int numUsedContainers, int numReservedContainers, Resource usedResources,
      Resource reservedResources, Resource neededResources, long memorySeconds,
      long vcoreSeconds) {
    ApplicationResourceUsageReport report =
        Records.newRecord(ApplicationResourceUsageReport.class);
    report.setNumUsedContainers(numUsedContainers);
    report.setNumReservedContainers(numReservedContainers);
    report.setUsedResources(usedResources);
    report.setReservedResources(reservedResources);
    report.setNeededResources(neededResources);
    report.setMemorySeconds(memorySeconds);
    report.setVcoreSeconds(vcoreSeconds);
    return report;
  }

Among them, usedResources is the current real-time occupied resources, including memory and CPU. This statistics is returned in the YarnScheduler interface:

org.apache.hadoop.yarn.server.resourcemanager.scheduler.YarnScheduler

  /**
   * Get a resource usage report from a given app attempt ID.
   * @param appAttemptId the id of the application attempt
   * @return resource usage report for this given attempt
   */
  @LimitedPrivate("yarn")
  @Evolving
  ApplicationResourceUsageReport getAppResourceUsageReport(
      ApplicationAttemptId appAttemptId);

The getAppResourceUsageReport method is called by RMAppAttemptImpl.getApplicationResourceUsageReport:

org.apache.hadoop.yarn.server.resourcemanager.rmapp.attempt.RMAppAttemptImpl

  @Override
  public ApplicationResourceUsageReport getApplicationResourceUsageReport() {
    this.readLock.lock();
    try {
      ApplicationResourceUsageReport report =
          scheduler.getAppResourceUsageReport(this.getAppAttemptId());
      if (report == null) {
        report = RMServerUtils.DUMMY_APPLICATION_RESOURCE_USAGE_REPORT;
      }
      AggregateAppResourceUsage resUsage =
          this.attemptMetrics.getAggregateAppResourceUsage();
      report.setMemorySeconds(resUsage.getMemorySeconds());
      report.setVcoreSeconds(resUsage.getVcoreSeconds());
      return report;
    } finally {
      this.readLock.unlock();
    }
  }

RMAppImpl.createAndGetApplicationReport will be called by ClientRMService.getApplications and ClientRMService.getApplicationReport. These two methods correspond to commands respectively.

yarn application - list
yarn application - status $applicationId

When displaying information in these two places, usedResources is not displayed. Maybe the author feels that this real-time resource usage statistics is not that important.

For details, see:

This constructor will be called during RMWebServices.getApp and RMWebServices.getApps. This is a service interface, and the corresponding URLs are:

http://resourcemanager/ws/v1/cluster/apps/$applicationId
http://resourcemanager/ws/v1/cluster/apps?state=RUNNING

The real-time resource usage in the return values ​​of these two interfaces is as follows:

<allocatedMB>56320</allocatedMB>
<allocatedVCores>21</allocatedVCores>

Corresponds to real-time memory usage and real-time CPU usage respectively;

For details, see:
org.apache.hadoop.yarn.server.resourcemanager.webapp.RMWebServices
