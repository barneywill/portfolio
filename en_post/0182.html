Spark cache unpersist cascade operation

📅 March 13, 2019
📖 1 min read
👁️ 1639 views

Question: If there are two DataFrames (or DataSets) in Spark, DataFrameA depends on DataFrameB, and both DataFrames are cached. After DataFrameB is unpersisted, the cache of DataFrameA will also become invalid. The official explanation is as follows:

When invalidating a cache, we invalid other caches dependent on this cache to ensure cached data is up to date. For example, when the underlying table has been modified or the table has been dropped itself, all caches that use this table should be invalidated or refreshed.

However, in other cases, like when user simply want to drop a cache to free up memory, we do not need to invalidate dependent caches since no underlying data has been changed. For this reason, we would like to introduce a new cache invalidation mode: the non-cascading cache invalidation.

The previous default mode was regular mode. In this mode, in order to ensure that the cached data is up to date (not expired), the unpersist of the cache will be cascaded, that is, all other caches that depend on the cache will be cleared (including indirect dependencies);
Starting from spark2.4, a new mode has been introduced: non-cascading mode. In this mode, the cache unpersist will not be cascaded;

The default level for cache operations of DataFrame/DataSet is MEMORY_AND_DISK. Unless MEMORY is manually specified and the memory is confirmed to be sufficient, the cache before unpersist seems unnecessary;
