Spark will pause for a few minutes between jobs

📅 December 27, 2018
📖 1 min read
👁️ 853 views

I encountered a problem today. In the Spark application, SQL is executed in a loop. Each SQL will write data to a table, such as

insert overwrite table test_table partition(dt) select * from test_table_another;

There is no other logic except executing SQL. Each SQL will correspond to a job. On the Spark web ui, you can see that there will be a pause between jobs for a few minutes, and it is very regular. There will be a pause between any two jobs. Isn't it amazing?

 

The answer is revealed:

When Spark executes insert overwrite table partition, it is divided into two parts, one is to execute select (read data), and the other is to execute load partition (write data). For details, see the execution plan;

Each SQL corresponds to a job. The select part (reading data) of this job does not include the load partition part (writing data). In order to be compatible with Hive, Spark directly uses Hive's metadata database. All ddl operations directly call Hive code through reflection (spark2.1 relies on hive1.2). This process is not included in the Spark job, so it seems that after the job is executed, it pauses for a few minutes before executing the next job. The few minutes of pause here are actually doing the load partition operation (writing data);

 

There is another problem here. When hive1.2 deletes files in loadPartition, it is a serial operation, which is very slow. This problem was changed to a thread pool in hive2. See the specific code and problem analysis for details:https://www.cnblogs.com/barneywill/p/10154922.html
