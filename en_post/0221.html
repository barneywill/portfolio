It can be seen that mesos-master has been providing resource offers to marathon, but has been rejected. After carefully checking the logs, we found that

I0216 01:01:12.527853 25338 master.cpp:7503] Re-registered agent 0548c9c0-dd5f-4b3a-8aca-4668f8aacb69-S9 at slave(1)@192.168.0.1:5051 (server1.bj) with cpus:8; mem:14861; disk:35829; ports:[31000-32000]

It was found that there is a problem with the resource range of mesos-slave, ports:[31000-32000], Nginx requires port 80, so it has been rejected. The official document about resources is described as follows:

--resources=VALUE

Total consumable resources per agent. Can be provided in JSON format or as a semicolon-delimited list of key:value pairs, with the role optionally specified.
As a key:value list: name(role):value;name:value...
To use JSON, pass a JSON-formatted string or use --resources=filepath to specify the resources via a file containing a JSON-formatted string. 'filepath' can be of the form file:///path/to/file or /path/to/file.
Example JSON:
[
{
"name": "cpus",
"type": "SCALAR",
"scalar": {
"value": 24
}
},
{
"name": "mem",
"type": "SCALAR",
"scalar": {
"value": 24576
}
}
]

Reference: http://mesos.apache.org/documentation/latest/configuration/agent/

 

Modify port range

# echo 'ports(*):[80-80000]' > /etc/mesos-slave/resources
# service mesos-slave restart

The previous error is gone, but a new one appears

# rm - f /var/lib/mesos/meta/slaves/latest
# service mesos-slave start

3 If you need to specify which machine to execute on, you can set constraints

Only allowed to execute on one machine

"constraints": [
[
"hostname",
"CLUSTER",
"server2.bj"
]
],

Allows execution on two machines, but only one can be started on each machine

"constraints": [
[
"hostname",
"UNIQUE"
],
[
"hostname",
"LIKE",
"server[1-2].bj"
]
],

Reference: https://mesosphere.github.io/marathon/docs/constraints.html

 

After deployment is complete

 

One more thing, I noticed that the status in the screenshot above is waiting, because I did a restart operation, but each of my apps was designated to be deployed on only one server. At this time, it will actually be stuck in waiting, because marathon will not stop the app first and then start it when restarting, but will continue to wait for resources from mesos-master. offer, the old app will be stopped only when there are available resources to start a new app. The app here will occupy port 80, so it is an infinite loop. At this time, the container can only be stopped manually from Docker;
