frp

Introduction

frp is a fast reverse proxy to help you expose a local server behind a NAT or firewall to the Internet. As of now, it supports TCP and UDP, as well as HTTP and HTTPS protocols, where requests can be forwarded to internal services by domain name.

download

Download the latest tag, download address:https://github.com/fatedier/frp

Install

Decompress separately on the server and client

tar xvf frp_0.37.0_linux_amd64.tar.gz

Server

Prepare configuration file: frps.ini

[common]
bind_port=7000
token=$token
dashboard_port=7500
dashboard_user=$user
dashboard_pwd=$pwd
log_file=/path/to/frp_0.37.0_linux_amd64/logs/frps.log
log_level=info
log_max_days=3
authentication_timeout=0
max_pool_count=50

Configure token (used for client to connect to server), dashboard_user and dashboard_pwd (used for management page)

start up

./frps - c frps.ini

After startup, access: http://$server_ip:7500
The account number and password are dashboard_user and dashboard_pwd

client

Prepare configuration file: frpc.ini

[common]
server_addr=$server_ip
server_port=7000
token=$token


[test_ssh]
type=tcp
local_ip=127.0.0.1
local_port=22
remote_port=$port

Similar to test_ssh, multiple configurations can be configured. Test_ssh indicates that the local port 22 is bound to the $port port of the remote server. That is, the client's port 22 can be indirectly accessed by accessing the $port of the remote server's $server_ip.

start up

./frps - c frpc.ini

Usage scenarios

A cloud host with an external network IP, configure the frp server on it, and then deploy the client on the intranet, bind the intranet port to the cloud host port, and achieve penetrating access to the intranet
