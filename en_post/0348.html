One of these two threads is reading and the other is writing. Looking at the source code of dubbo monitor, we found:

 

There will be two threads in the monitor, one keeps writing statistical logs, and the other performs draw operations every 300s;

Every day's logs in the monitor will be saved in a log directory. Enter one day's log directory to view the log size:

I found that the daily log is only tens of MB, and the result of the above iotop view is that the read is 1520K/s and the write is 3.43M/s, so to rule out the write problem, the problem should be with draw. Looking at the source code of draw, I found that draw will continuously read the statistical log and perform drawing operations at the same time.

 

The log directory will be traversed in draw, and the log reading operation will be performed in the appendData method. Since the monitor has been running for a long time, there are many directories saved on a daily basis. Each draw needs to traverse these directories and read files. The historical data has not changed but log reading and drawing will continue to be performed again. The problem should be here;
