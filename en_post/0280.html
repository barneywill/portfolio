After Spark on YARN submits the task, the execution progress is always 10%

📅 January 10, 2019
📖 3 min read
👁️ 2404 views

spark 2.1.1

The system hopes to monitor the execution progress of the Spark on YARN task, but during the monitoring process it is found that the execution progress is always 10% after the task is submitted. Until the execution is successful or fails, the progress will suddenly change to 100%, which is amazing.

 

 Let’s look at the Spark on YARN task submission process:

 

When Spark on YARN submits a task, mainClass will be modified to Client

childMainClass = "org.apache.spark.deploy.yarn.Client"

For details on the Spark-submit process, see:https://www.cnblogs.com/barneywill/p/9820684.html

The calling process here is Client.main->run->submitApplication->createContainerLaunchContext, and then amClass is set, and eventually ApplicationMaster is called, because ExecutorLauncher also calls ApplicationMaster internally, as follows:

org.apache.spark.deploy.yarn.ExecutorLauncher

object ExecutorLauncher {

  def main(args: Array[String]): Unit = {
    ApplicationMaster.main(args)
  }

}

The calling process here is ApplicationMaster.main->run. RunDriver or runExecutorLauncher will be called in run, and eventually registerAM will be called, which will call YarnAllocator.allocateResources, and then a thread will be started in launchReporterThread, which will also continuously call YarnAllocator.allocateResources. Let's look at YarnAllocator:

org.apache.spark.deploy.yarn.YarnAllocator

  def allocateResources(): Unit = synchronized {
    updateResourceRequests()

    val progressIndicator = 0.1f
    // Poll the ResourceManager. This doubles as a heartbeat if there are no pending container

    val allocateResponse = amClient.allocate(progressIndicator)

It can be seen that the progress is set to 0.1, which is 10%, and it is hard-coded, so the execution progress of Spark on YARN is always 10%, so it seems futile to monitor the task progress of Spark on YARN;
