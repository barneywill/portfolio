Java basics: simply modify the class in the jar package

📅 March 18, 2019
📖 3 min read
👁️ 5565 views

Sometimes it is necessary to modify a certain class in one of the jars among many jars (assuming that these jars are all located in the lib directory), and there is no original code or IDE. In this case, the simplest way is:

1 Enter the lib directory

# cd lib
# ls
test.jar dependency1.jar dependency2.jar

2 View the class structure in the jar package to be modified

$ unzip - l test.jar

or

$ vim test.jar

3 Unzip the jar package to be modified

$ mkdir test_dir
$ unzip test.jar -d test_dir

4 Check the jdk version of the class

$ vi - b test_dir/package/Class.class
:%!xxd

0000000: cafe babe 0000 0032 0123 0700 0201 0023 .......2.#.....#

Take the 15th-16th digit, which is 32 in the above example.

5 Place the file to be modified in the same directory as class (if you don’t have the source code, you can try decompiling it), and modify

$ vi test_dir/package/Class.java

6 Collect classpath

Since there may be many jar packages, use the command to generate

$ ls *.jar|sed ':a;N;$!ba;s/\n/:/g'
test.jar:dependency1.jar:dependency2.jar

Note that under Linux it is: separate, under Windows it is; separate

7 compile

$ javac - help
Usage: javac <options> <source files>
where possible options include:
  -g                         Generate all debugging info
  -g:none                    Generate no debugging info
  -g:{lines,vars,source}     Generate only some debugging info
  -nowarn                    Generate no warnings
  -verbose                   Output messages about what the compiler is doing
  -deprecation               Output source locations where deprecated APIs are used
  -classpath <path>          Specify where to find user class files and annotation processors
  -cp <path>                 Specify where to find user class files and annotation processors
  -sourcepath <path>         Specify where to find input source files
  -bootclasspath <path>      Override location of bootstrap class files
  -extdirs <dirs>            Override location of installed extensions
  -endorseddirs <dirs>       Override location of endorsed standards path
  -proc:{none,only}          Control whether annotation processing and/or compilation is done.
  -processor <class1>[,<class2>,<class3>...] Names of the annotation processors to run; bypasses default discovery process
  -processorpath <path>      Specify where to find annotation processors
  -parameters                Generate metadata for reflection on method parameters
  -d <directory>             Specify where to place generated class files
  -s <directory>             Specify where to place generated source files
  -h <directory>             Specify where to place generated native header files
  -implicit:{none,class}     Specify whether or not to generate class files for implicitly referenced files
  -encoding <encoding>       Specify character encoding used by source files
  -source <release>          Provide source compatibility with specified release
  -target <release>          Generate class files for specific VM version
  -profile <profile>         Check that API used is available in the specified profile
  -version                   Version information
  -help                      Print a synopsis of standard options
  -Akey[=value]              Options to pass to annotation processors
  -X                         Print a synopsis of nonstandard options
  -J<flag>                   Pass <flag> directly to the runtime system
  -Werror                    Terminate compilation if warnings occur
  @<filename>                Read options and filenames from file

actual command

$ javac - cp test.jar:dependency1.jar:dependency2.jar - source 1.6 - target 1.6 - sourcepath test_dir - d test_dir test_dir/package/Class.java

8 Re-package the jar package

$ cd test_dir
$ zip -r test.jar ./*

9 Delete the temporary directory and original jar

$ cd ..
$ cp test_dir/test.jar test.jar
$ /bin/rm - rf test_dir

10 Test modifications take effect
