Garbled Text When Hive Reads gzip Files

📅 May 19, 2022
📖 1 min read
👁️ 599 views

background

Hive reads plain text data, whether in original format, gzip, or bzip, and can automatically recognize it without modifying the table creation statement or setting.
However, after using gobblin to enable gzip compression and saving the file and reading it with Hive, garbled characters occur.

position

First suspect that the file is damaged

The file written by gobblin after turning on compression is: *.txt.gzip. Download the file locally and use the gzip command to decompress and exclude it normally.

Secondly, I suspect that there is incompatibility between gzip versions.

That is, the versions of gobblin writing gzip and Hive reading gzip are not compatible. Check the code of gobblin writing files and find that the

java.util.zip.GZIPOutputStream

Both jdk jar packages are used for reading and Hive, so they are excluded.

Finally, I suspect that Hive has a problem with gzip format recognition.

Looking at the code of Hive reading files, we found that the gzip format is recognized based on the hard-coded gz suffix. After changing the gzip suffix to gz suffix, Hive reads normally and finds the reason.
