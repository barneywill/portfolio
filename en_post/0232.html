SSH jump exception after upgrading openssh to 7.4

📅 February 13, 2019
📖 3 min read
👁️ 7512 views

Change all file permissions under /etc/ssh to 600

# chmod 600 /etc/ssh/*

Then use the tested sshd process to jump to port 8822, everything is normal, but the sshd service still fails to start. It is suspected that the current sshd process is not started through the service, so the sshd service keeps restarting but cannot bind the port. Kill the sshd process, and then see that the sshd service finally starts normally.

But there is another error: Bind to port 22 on :: failed: Address already in use. This is because in the configuration file

$ vi /etc/ssh/sshd_config
#Port 22
#Protocol 2,1
#ListenAddress 0.0.0.0
#ListenAddress ::

By default, port 22 of ipv4 and ipv6 will be bound. Uncomment two of the lines.

Port 22
#Protocol 2,1
ListenAddress 0.0.0.0
#ListenAddress ::

Start normally

Feb 13 15:30:04 $server systemd[1]: Starting OpenSSH server daemon...
Feb 13 15:30:04 $server sshd[4731]: Could not load host key: /etc/ssh/ssh_host_dsa_key
Feb 13 15:30:04 $server sshd[4731]: Server listening on 0.0.0.0 port 22.

But the process will disappear after a while, check sshd.service

# cat /usr/lib/systemd/system/sshd.service
[Unit]
Description=OpenSSH server daemon
Documentation=man:sshd(8) man:sshd_config(5)
After=network.target sshd-keygen.service
Wants=sshd-keygen.service

[Service]
Type=notify
EnvironmentFile=/etc/sysconfig/sshd
ExecStart=/usr/sbin/sshd -D $OPTIONS
ExecReload=/bin/kill -HUP $MAINPID
KillMode=process
Restart=on-failure
RestartSec=42s

[Install]
WantedBy=multi-user.target

It seems to be caused by the process being aborted due to constant startup timeout;

# vi /usr/lib/systemd/system/sshd.service
ExecStart=/usr/sbin/sshd $OPTIONS

Remove -D, then kill the previous sshd, and then restart sshd

# systemctl daemon-reload
# systemctl start sshd

At this point, the sshd service has been restored and the ssh jump has been restored. Therefore, when upgrading openssh to 7.4, you must modify the file permissions under /etc/ssh/, otherwise ssh protocol 2 will be disabled and the previous key will become invalid. At the same time, sshd.service must be modified; wait, ansible will report an error.

192.168.0.1 | FAILED | rc=-1 >>
failed to open a SFTP connection (Channel closed.)

View sshd_config

# vi /etc/ssh/sshd_config
Subsystem sftp /usr/libexec/sftp-server

It was found that the sftp-server path does not exist /usr/libexec/sftp-server. The actual path is /usr/libexec/openssh/sftp-server. After modifying it, restart sshd. The above problem is fixed. After a while, scp also reports an error.

# scp 192.168.0.1:/file1 .
command-line: line 0: Bad configuration option: PermitLocalCommand

This is caused by the mismatch between scp, sftp and ssh versions. Use yum to check that these commands are all in the openssh-clients package, but the last modification time of these commands is different. Reinstall openssh-clients.

# yum reinstall openssh-clients

Then the last modification time of these commands are consistent, and the problem disappears;
