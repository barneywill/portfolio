Spark SQL limit implementation principle

📅 December 21, 2018
📖 1 min read
👁️ 3666 views

The implementation of limit in Hive has been discussed before. For details, see https://www.cnblogs.com/barneywill/p/10109217.html
Let’s look at the implementation of limit in Spark SQL. First, look at the execution plan:

spark-sql> explain select * from test1 limit 10;
== Physical Plan ==
CollectLimit 10
+- HiveTableScan [id#35], MetastoreRelation temp, test1
Time taken: 0.201 seconds, Fetched 1 row(s)

CollectLimit corresponding to limit, the corresponding implementation class is

org.apache.spark.sql.execution.CollectLimitExec

case class CollectLimitExec(limit: Int, child: SparkPlan) extends UnaryExecNode {
...
  protected override def doExecute(): RDD[InternalRow] = {
    val locallyLimited = child.execute().mapPartitionsInternal(_.take(limit))
    val shuffled = new ShuffledRowRDD(
      ShuffleExchange.prepareShuffleDependency(
        locallyLimited, child.output, SinglePartition, serializer))
    shuffled.mapPartitionsInternal(_.take(limit))
  }

It can be seen that the implementation is very simple. First, call SparkPlan.execute to get the RDD of the result, then take the first limit rows from each partition to get a new RDD, then turn this new RDD into a partition, and then take the first limit rows, so as to get the final result.
