📅 October 18, 2018
📖 3 min read
👁️ 3652 views

Recently, many region servers in the HBase cluster have hung up. Looking at the log of one of the RegionServer1, I found that the server was under great pressure when it hung up at 17:17:14. There were a lot of responseTooSlow and a lot of gc, but there was still a lot of memory left at that time. It was not because oom was killed.

What is taken here is the sessionTimeout in ServerCnxn. This value is initialized in ZooKeeperServer.

        int minSessionTimeout = getMinSessionTimeout();

        if (sessionTimeout < minSessionTimeout) {

            sessionTimeout = minSessionTimeout;

        }

        int maxSessionTimeout = getMaxSessionTimeout();

        if (sessionTimeout > maxSessionTimeout) {

            sessionTimeout = maxSessionTimeout;

        }

You can see that it will be limited according to minSessionTimeout and maxSessionTimeout

    public int getMaxSessionTimeout() {

        return maxSessionTimeout == - 1 ? tickTime * 20 : maxSessionTimeout;

    }

Since the ZooKeeper server tickTime is set to 2000ms, maxSessionTimeout will be set to 40000ms by default, so to solve this problem you need to modify zk's maxSessionTimeout;
