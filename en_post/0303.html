HDFS file create is written normally, but append writes an error

📅 December 21, 2018
📖 7 min read
👁️ 1505 views

Recently, I discovered a problem when writing files in HDFS. Create writes normally, but append writes an error. It can be reproduced every time. The code example is as follows:

        FileSystem fs = FileSystem.get(conf);
        OutputStream out = fs.create(file);
        IOUtils.copyBytes(in, out, 4096, true); //normal
        out = fs.append(file);
        IOUtils.copyBytes(in, out, 4096, true); //Report an error

I checked the problematic file through the HDFS fsck command and found that there is only one copy. Is this the reason?

When appending a file, the last block of the file will be taken out first, and then it will be checked to see if the block meets the copy requirements. If it does not, an exception will be thrown. If it does, it will be ready to write;
It seems that the reason is indeed because there is only one copy of the file, causing append to report an error. Then why does the newly created file only have one copy? Later, it was found that the reason was due to a problem with the rack configuration. For details, see https://www.cnblogs.com/barneywill/p/10114504.html
