After hive2.0, there is no progress information when executing SQL through beeline.

📅 December 27, 2018
📖 6 min read
👁️ 6005 views

1 question

In hive1.2, there is progress information when using Hive or beeline to execute SQL. However, after upgrading to hive2.0, only Hive has progress information when executing SQL. Beeline is completely silent when executing SQL. During the process of waiting for the result, you have no idea where the execution is.

2. Code analysis

For the detailed process of Hive executing SQL, please see:https://www.cnblogs.com/barneywill/p/10185168.html

Executing SQL in Hive will eventually call Driver.run, and run will call execute. Let’s look at the execute code directly:

  private void logMrWarning(int mrJobs) {
    if (mrJobs <= 0 || !("mr".equals(HiveConf.getVar(conf, ConfVars.HIVE_EXECUTION_ENGINE)))) {
      return;
    }
    String warning = HiveConf.generateMrDeprecationWarning();
    LOG.warn(warning);
    warning = "WARNING: " + warning;
    console.printInfo(warning);
    // Propagate warning to beeline via operation log.
    OperationLog ol = OperationLog.getCurrentOperationLog();
    if (ol != null) {
      ol.writeOperationLog(LoggingLevel.EXECUTION, warning + "\n");
    }
  }

It can be seen that the progress information seen in the Hive command is output through console.printInfo;
Noticed a detail. Although there is no progress information in beeline, there is a warning message:

WARNING: Hive-on-MR is deprecated in Hive 2 and may not be available in the future versions. Consider using a different execution engine (i.e. spark, tez) or using Hive 1.X releases.

This warning information is output through the following code:

    OperationLog ol = OperationLog.getCurrentOperationLog();
    if (ol != null) {
      ol.writeOperationLog(LoggingLevel.EXECUTION, warning + "\n");
    }

Therefore, if you let beeline execute SQL and there is progress information, it must be output in the same way;
