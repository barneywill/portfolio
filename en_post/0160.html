Docker 7 - About Docker latest tag

📅 March 26, 2019
📖 1 min read
👁️ 3523 views

Docker images have a tag named latest which doesn’t work as you expect.
Latest is just a tag with a special name.
“Latest” simply means “the last build/tag that ran without a specific tag/version specified”.
Just version your tags. Every time.

The Docker image has a tag called latest. The latest is generated by the latest build or tag that does not specify a version.

Let’s see the experiment below:

$ docker tag imagename localhost:5000/imagename
$ docker push localhost:5000/imagename

In this way, an imagename with the latest version can be created on the repository. The next update operation is as follows:

1) First stop using the old image container and delete it, then delete the old image

$ docker stop $container_id
$ docker rm $container_id
$ docker rmi localhost:5000/imagename

2) Same as above

$ docker tag imagename localhost:5000/imagename
$ docker push localhost:5000/imagename

This approach does not preserve historical versions;

A better approach would be:

1) Version 1

$ docker tag imagename localhost:5000/imagename:1
$ docker push localhost:5000/imagename:1
$ docker tag imagename localhost:5000/imagename
$ docker push localhost:5000/imagename

At this time latest=1

2) Version 2

$ docker tag imagename localhost:5000/imagename:2
$ docker push localhost:5000/imagename:2

$ docker stop $container_id
$ docker rm $container_id
$ docker rmi localhost:5000/imagename
$ docker tag imagename localhost:5000/imagename
$ docker push localhost:5000/imagename

At this time latest=2
