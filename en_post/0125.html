Kudu 6 - Kudu tserver memory usage statistical analysis

📅 June 01, 2019
📖 1 min read
👁️ 3592 views

When Kudu tserver takes up too much memory, it will reject some write requests. The log is as follows:

19/06/01 13:34:12 INFO AsyncKuduClient: Invalidating location 34b1c13d04664cc8bae6689d39b08b77($kudu_tserver:7050) for tablet 858c055c456549569af77d14eaf997e5: Service unavailable: Soft memory limit exceeded (at 92.36% of capacity). See https://kudu.apache.org/releases/1.7.0-cdh5.16.1/docs/troubleshooting.html

1 Check the detailed memory usage of tserver

http://$kudu_tserver:8050/mem-trackers

The page is divided into two parts:

Process memory usage is the overall usage

Memory usage by subsystem is a detailed ratio, which may seem complicated at first glance, but is actually a tree structure that is cascaded through parent.

For example, the total occupancy of root is 1.6G, and the logcache under root occupies 277K. Let’s look down.

block_cache-sharded_lru_cache occupies 246M, and the server occupies 1.4G. The server is divided into many tablets. In addition to tablets, there are

log_block_manager occupies 438M;

 

If you find that some tablets occupy a lot of memory and want to see which table they are in, you can run the following command:

sudo - u kudu kudu remote_replica list $kudu_tserver

Regarding the memory estimation of Kudu, it is related to the size of the data, the number of tablets and the number of active replicas. For details, see:

https://kudu.apache.org/docs/scaling_guide.html#memory
