How to choose the format when creating a Hive table

📅 December 12, 2018
📖 8 min read
👁️ 2585 views

Common formats

textfile

It is a format that requires defining delimiters, takes up a lot of space, has the lowest reading and writing efficiency, and is very prone to conflicts (delimiters). It is basically only used when data needs to be imported, such as importing csv files;

ROW FORMAT DELIMITED

  FIELDS TERMINATED BY '\u0001'

  LINES TERMINATED BY '\n'

STORED AS TEXTFILE

json

After hive3.0, JSON format is officially supported. Before, you needed to use a third party and import jar.http://www.congiu.net/hive-json-serde/，

add jar hdfs://nn/jarpath/json-udf-1.3.8-jar-with-dependencies.jar;
add jar hdfs://nn/jarpath/json-serde-1.3.8-jar-with-dependencies.jar;

It takes up the largest space and has low reading and writing efficiency. It is basically only used when data needs to be imported, such as importing JSON files;

ROW FORMAT SERDE 'org.openx.data.jsonserde.JsonSerDe'
STORED AS TEXTFILE

xml

http://central.maven.org/maven2/com/ibm/spss/hive/serde2/xml/hivexmlserde/1.0.0.0/hivexmlserde-1.0.0.0.jar

   CREATE TABLE xml_bank(customer_id STRING, income BIGINT, demographics 
   map<string,string>, financial map<string,string>)
   ROW FORMAT SERDE 'com.ibm.spss.hive.serde2.xml.XmlSerDe'
   WITH SERDEPROPERTIES (
   "column.xpath.customer_id"="/record/@customer_id",
   "column.xpath.income"="/record/income/text()",
   "column.xpath.demographics"="/record/demographics/*",
   "column.xpath.financial"="/record/financial/*"
    )
    TBLPROPERTIES (
    "xmlinput.start"="<record customer",
    "xmlinput.end"="</record>"
    );

lzo

Compared with textfile, it has LZO compression and takes up less space;

ROW FORMAT DELIMITED
FIELDS TERMINATED BY '\t'
STORED AS INPUTFORMAT
'com.hadoop.mapred.DeprecatedLzoTextInputFormat'
OUTPUTFORMAT
'org.apache.hadoop.hive.ql.io.HiveIgnoreKeyTextOutputFormat'

orc

Column storage takes up minimal space and is very suitable for data warehouse;

STORED AS ORC

compression

STORED AS ORC TBLPROPERTIES ("orc.compression"="ZLIB")

STORED AS ORC TBLPROPERTIES ("orc.compression"="SNAPPY")

Note that before setting the ORC compression format, you must set it first:

set hive.exec.orc.compression.strategy=COMPRESSION;

Otherwise, compression will not take effect;

parquet

Column storage takes up space in the middle. If Spark is used for processing later, Parquet is the best format;

 STORED AS PARQUET

parquet+snappy

STORED AS PARQUET TBLPROPERTIES ("parquet.compression"="SNAPPY")

  • In terms of data size and query efficiency, the best performer is Presto+ORC+snappy;
  • The best format under Hive is ORC snappy, which has the smallest data size and the fastest query;
  • After Hive switches the engine to Spark, there is some improvement in Parquet format query, but when occupying the same resources, it is far faster than using Spark SQL directly;
  • After spark2.3, the ORC format has been greatly optimized compared to before, and it is already very close to the Parquet format;
  • The performance of Impala+Parquet+HDFS is similar to that of Impala+Kudu. The advantage of Kudu is that it supports real-time updates;
  • drill seems unnecessary;
  • Parquet in spark2.4.0 is 2.4, and Parquet supports column index starting from 2.5. It is expected that future Spark versions will query Parquet faster;
  • Impala's support for ORC starts in 3.1 as part of an experimental feature;
