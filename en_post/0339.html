2. Problem analysis

MethodPositionTest An anonymous function anonfun is defined. This anonymous function is called in RDD.map, that is, executed in the Executor. The anonymous function relies on the mapFun method to trigger the initialization of the class: MethodPositionTest$.<clinit>. During initialization, spars outside main will be executed. k initialization code, that is, creating SparkConf and SparkContext in the Executor, this should not happen. There can only be one SparkContext in a Spark application and it should be on the Driver side instead of the Executor, and it will cause an error after it occurs. The code is as follows:

org.apache.spark.SparkContext

  try {

    _conf = config.clone()

    _conf.validateSettings()

 

    if (!_conf.contains("spark.master")) {

      throw new SparkException("A master URL must be set in your configuration")

 

    }

 

Question 1) Why does the Driver side not report an error that the master cannot be found, but the Executor side reports an error?

The Spark application code is as follows:

val sparkConf = new SparkConf().setAppName(getName)

Here SparkConf only sets the AppName. Why does it not report an error on the Driver side that the master cannot be found, but an error is reported on the Executor side? Here you need to look at the execution process of Spark Submit. For details, see https://www.cnblogs.com/barneywill/p/9820684.html

When executing on the Driver side, SparkSubmit will uniformly set various parameters including command line, configuration files, system environment variables, etc. to the system environment variables.

    for ((key, value) <- sysProps) {

      System.setProperty(key, value)

    }

Then SparkConf will load the configuration from the system environment variables by default

    for ((key, value) <- Utils.getSystemProperties if key.startsWith("spark.")) {

      set(key, value, silent)

    }

Therefore, the SparkConf on the Driver side will contain all parameters, but not on the Executor side.

 

Question 2) When the Spark-related initialization code is outside main, why does it sometimes report an error and sometimes not?

The specific situation is as follows:
1) If the transformation in main (the map method in the example) does not rely on external function calls, it is normal;
2) If the transformation in main (the map method in the example) depends on the function in main, an error will be reported;
3) If the transformation inside main (the map method in the example) depends on a function outside main, an error will be reported;

You can see the reason by decompiling the code. The decompiled code of the example MethodPositionTest is as follows:

To sum up, it is not recommended to put the Spark initialization code outside main, as it is easy to cause problems.
