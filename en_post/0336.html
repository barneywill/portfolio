How to implement automatic switching between master and slave on YARN ResourceManager page

📅 December 12, 2018
📖 1 min read
👁️ 1769 views

The components of HDFS, YARN, and HBase support multiple masters to achieve automatic active-standby switching. HDFS and HBase can access the page normally regardless of whether they access the primary master or the standby master. However, YARN is special. Only the primary master's page can be accessed. The standby master will return Refresh and redirect after 3 seconds;

One way is to provide two domain names, corresponding to the masters of the two yarns. Once the master is switched, you need to manually switch to the other one. Is there a better way?

 

The process of accessing the standby master is as follows:

It can be seen that the backup master response http status is 200, including the Refresh header, and the body isThis is standby RM. Redirecting to the current active RM:***

Is it possible to configure automatic switching on the load balancer (such as Nginx)? The illegal response here needs to determine whether the header contains 'Refresh' or the body contains 'This is standby RM'

 

1) Passive switching, supports http status and timeout and other judgments, not satisfied

http://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_next_upstream

proxy_next_upstream error | timeout | invalid_header | http_500 | http_502 | http_503 | http_504 | http_403 | http_404 | http_429 | non_idempotent | off ...;

 

2) Active health check, the most commonly used open source module, only supports http status level health check, which is not satisfactory

https://github.com/yaoweibin/nginx_upstream_check_module

  check_http_expect_alive

    syntax: *check_http_expect_alive [ http_2xx | http_3xx | http_4xx |

    http_5xx ]*

    default: *http_2xx | http_3xx*

    context: *upstream*

    description: These status codes indicate the upstream server's http

    response is ok, the backend is alive.

 

3) The paid version of Nginx ngx_http_upstream_hc_module supports the judgment of header and body, which can satisfy

Dynamically configurable group with periodic health checks is available as part of our commercial subscription:

http://nginx.org/en/docs/http/ngx_http_upstream_hc_module.html

    match active {

        body !~ "This is standby RM";

    }
