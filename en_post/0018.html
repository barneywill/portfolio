Background

Some students reported that messages were lost in a certain Kafka topic (the consumption was less than the production), and the loss rate was about 20%.

Troubleshooting

The replication-factor of the problematic topic is 2, the number of partitions is 5, and the status of the topic is as follows:

There is a topic in the Under Replicated state, with only one ISR. Node 193 did not come in after being kicked out, and it was not replaced with other nodes.

First, check whether the producer reports an error. In Kafka 2.0, the producer sending method is async+interceptor. You can specify a custom interceptor through interceptor.class.

All errors will call back the interceptor

By adding an interceptor and printing the error log in onSendError, an error is reported:

ERROR ninebot.iot.hub.KafkaTest 100 - send error :Messages are rejected since there are fewer in-sync replicas than required.
org.apache.kafka.common.errors.NotEnoughReplicasException: Messages are rejected since there are fewer in-sync replicas than required.

The direct reason for the error is: partition-0 has only 1 replica, which is less than the configured 2. All messages sent to this partition will be rejected.

Why does a ReplicaFetcherThread error cause 25 partitions to be eliminated?

There is a variable in ReplicaFetcherManager's parent class AbstractFetcherManager

private[server] val fetcherThreadMap = new mutable.HashMap[BrokerIdAndFetcherId, AbstractFetcherThread]

This map will use brokerId and fetcherId as keys to store ReplicaFetcherThread. It can be considered that one source broker corresponds to one fetcher thread. This fetcher thread will be responsible for the synchronization of all partitions on the source broker. The error of ReplicaFetcherThread will cause the entire thread to exit.

Then it will affect the synchronization of all partitions on the source broker, causing these partitions to be kicked out at the same time 193

Why did the deletion fail at that time?

I found that this bug has been mentioned on the official jira of Kafka.

https://issues.apache.org/jira/browse/KAFKA-6388

and the bug has been fixed

https://github.com/apache/kafka/pull/6006/commits/f39a9f533f7bedf28dbaca7644b99808e163ea4d

Remove the prev check and exception throwing code

Upgrade Kafka from 2.0 to 2.1. This bug has been fixed since 2.1
