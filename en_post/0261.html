ambari2.7.3 (hdp3.1) install impala2.12 (automatically install the latest)

Ambari's HDP does not natively support Impala installation. Here is how to make Ambari support Impala installation through mpack:

1. Install Service

1 download

# wget https://github.com/cas-bigdatalab/ambari-impala-service/raw/master/ambari-impala-mpack-2.6.0-0816.tar.gz

2 installation

 # ambari-server install-mpack --mpack=/path/to/ambari-impala-mpack-2.6.0-0816.tar.gz --verbose

3 Restart

 # ambari-server restart

Visit the Ambari page and find that there is no Impala in services. Check mpack.JSON and find the problem:

/var/lib/ambari-server/resources/mpacks/ambari-impala-mpack-2.6.0-0816/mpack.json

{"name": "ambari-impala-mpack", "prerequisites": {"max-ambari-version": "", "min-ambari-version": "2.4.0.0"}, "artifacts": [{"type": "service-definitions", "name": "ambari-common-services", "source_dir": "common-services"}, {"service_versions_map": [{"service_name": "IMPALA", "applicable_stacks": [{"stack_name": "HDP", "stack_version": "2.6"}], "service_version": "2.6.0"}], "type": "stack-addon-service-definitions", "name": "ambari-addon-services", "source_dir": "addon-services"}], "version": "2.6.0-0816", "type": "full-release", "description": "Ambari Management Pack ambari-impala-mpack"}

Modify hdp version, add 3.1

{"stack_name": "HDP", "stack_version": "2.6"}

Repackage Ambari-Impala-mpack-2.6.0-0816.tar.gz

Note: The Impala version does not need to be modified, the latest one will be installed by default;

4 Uninstall

ambari-server uninstall-mpack --mpack-name=ambari-impala-mpack

5 Installation (same as above)

6 Restart (same as above)

2. Install Impala

Follow the page prompts to add repo

# cat /etc/yum.repos.d/impala.repo
[cloudera-cdh5]
# Packages for Cloudera's Distribution for Hadoop, Version 5, on RedHat or CentOS 7 x86_64
name=Cloudera's Distribution for Hadoop, Version 5
baseurl=https://archive.cloudera.com/cdh5/redhat/7/x86_64/cdh/5/
gpgkey =https://archive.cloudera.com/cdh5/redhat/7/x86_64/cdh/RPM-GPG-KEY-cloudera
gpgcheck = 1

Note that this is redhat7, you can change 7 to 6 as needed;

The method signature exists. Let's analyze the NoSuchMethodError carefully. This error does not mean that the method does not exist, otherwise the compilation will not pass, but because the jar package conflicts. There are two identical classes, one has this method and the other does not. Once the method of the second class is loaded during runtime, a NoSuchMethodError error will be reported. Then check other jars and indeed the problem is found.

Check the datanucleus related jars under /usr/lib/Impala/lib/:

datanucleus-api-jdo-3.2.6.jar
datanucleus-core-3.2.12.jar
datanucleus-rdbms-3.2.12.jar

Check through javap that these jar packages do not have org.datanucleus.PersistenceNucleusContext, and then look at the version hive2.1.0 depends on.

datanucleus-core-4.1.6.jar

And it cannot be solved by adding jar to /usr/lib/Impala/lib/. It can only be solved by downgrading the Hive version to 1.2.1, because this version of Hive uses datanucleus3. So far, the problem has been solved, and both Impala-catalog and Impala-server have been started successfully;
