The failed task is defined as follows

<action name="test_spark_task"> 

        <spark xmlns="uri:oozie:spark-action:0.1"> 

            <job-tracker>${job_tracker}</job-tracker> 

            <name-node>${name_node}</name-node> 

            <master>${jobmaster}</master>

You can see the application corresponding to application_1537326594090_5663 on YARN as follows:

application_1537326594090_5663       hadoop oozie:launcher:T=spark:W=test_wf:A=test_spark_task:ID=0012077-180830142722522-oozie-hado-W         Oozie Launcher

 

View application_1537326594090_5663 log discovery

2018-09-25 10:52:05,237 [main] INFO  org.apache.hadoop.yarn.client.api.impl.YarnClientImpl  - Submitted application application_1537326594090_5664

 

The application corresponding to application_1537326594090_5664 on YARN is as follows

application_1537326594090_5664       hadoop    TestSparkTask SPARK

 

That is, application_1537326594090_5664 is the Spark task corresponding to Action. Why is there an extra step in the middle? Please see the class structure and core code for details. https://www.cnblogs.com/barneywill/p/9895225.html

Briefly speaking, when Oozie executes an Action, that is, ActionExecutor (the main subclass is JavaActionExecutor, Hive, Spark and other actions are subclasses of this class), JavaActionExecutor will first submit a LauncherMapper (map task) Go to YARN, where LauncherMain will be executed (the specific action is its subclass, such as JavaMain, SparkMain, etc.), the Spark task will execute SparkMain, and org.apache.Spark.deploy.SparkSubmit will be called in SparkMain to submit the task.

 

If a Spark task is submitted, then the applicationId of the actual task can be tracked according to the above method;
If the hive2 task you submitted is actually started using beeline, starting from hive2, the log of the beeline command has been simplified. Unlike the Hive command, you can see the detailed applicationId and progress. There are two methods:

1) Modify the Hive code so that the beeline command has the same detailed log output as the Hive command.

For details, see:https://www.cnblogs.com/barneywill/p/10185949.html

2) Manually search for tasks based on application tag

When Oozie uses beeline to submit a task, it will add a mapreduce.job.tags parameter, such as

--hiveconf
mapreduce.job.tags=oozie-9f896ad3d40c261235dc6858cadb885c

However, this tag cannot be found from the YARN application command and can only be searched manually one by one (the actual started tasks will be incremented on the applicationId of the current LuancherMapper).

Then you can see the actual started applicationId

 

In addition, you can also see the detailed information of the application from the job history server, such as configuration, tasks, etc.

To view the complete SQL of Hive task execution, please see:https://www.cnblogs.com/barneywill/p/10083731.html
