Cardinality Estimate cardinality counting probability algorithm

Those who have read "Programming Pearls" should still remember the Case at the beginning. The approximate scene is:

A friend of the author who works in a telephone company wants to count the number of different phone numbers over a period of time. The number of phone numbers is very large, and the memory at that time is very small, so it is not possible to put all the phone numbers in the memory and repeat the statistics. His friend is very distressed.

The author cleverly thought of using a bit array to solve the problem. Each phone number can be mapped to the index of the bit array. All bits in the initial state of the bit array are 0. All phone numbers are processed one by one: set the corresponding position of the bit array to 1. After processing, just count how many 1's there are in the bit array.

Example: [0,1,0,0,0,1,0,...] This bit array indicates that 2 and 5 exist

I have to say that this idea is very subtle, that is, it reduces the memory usage (if all 8-digit phone numbers are put into the memory, it will take 381M (each phone number is saved as an Integer and takes up 4Byte calculation), but using a bit array only takes 11M), and only needs two loops to get the result;

 

This is a cardinality counting problem, Cardinality: estimating the number of distinct elements.

1 Bitmap

The method mentioned above is to use bitmap. The idea is to map each element in the dataset to a bit without allowing conflicts. The memory space required is approximately the base * 1 bit (100,000,000 bit in the above example), and the counting is accurate;

But when the base is very large, even the bitmap memory cannot fit in it!

The good news is that if counting accuracy is not required (allowing a certain range of error), you can use a probability estimation algorithm:

2 LC：Linear Counting

formula

Among them: n is the estimated value, m is the bitmap size, Vn is the ratio of 0 occurrences in the bitmap, such as 0.1;

principle

Using a fixed-size hashtable to store the dataset, you can imagine:

  • The smaller the base of the dataset, the emptier the hashtable. When the base is 0, all keys in the hashtable are empty.
  • The larger the cardinality of the dataset, the fuller the hashtable and the more conflicts. When the cardinality is infinite, all keys in the hashtable are occupied and each key has a large number of conflicts.

Therefore, the cardinality of the dataset can be estimated based on the occupied keys in the hashtable. The characteristics of the logarithmic curve are mainly used here (the section 0<x<1):

process

Initialize a bitmap with all bits set to 0. Each element of the dataset is hashed to a bit of the bitmap. After hashing, the corresponding bit position is set to 1. Conflicts are allowed in hashing. Finally, the base is estimated by a formula based on the number of 0s in the bitmap and the size of the bitmap;

Note: Although LC also uses bitmap, compared with the original bitmap algorithm, the bitmap size of LC can be much smaller than the base because LC's mapping allows conflicts. In addition, the bitmap size can be set to determine the size of the error;

3 LLC：LogLog Counting

formula


Among them: m is the number of buckets, M is the set of buckets, k is the number of digits used for bucketing, ρ is the first subscript of 1 in the bit array, which is the index, and E is the estimated value;

principle

Let’s look at the process of tossing a coin. The process of tossing a coin is a Bernoulli process. Each result is either 0 or 1, and the probability is 1/2. Assume that a coin tossing game is defined as tossing until 1, which may be the first It is possible to toss 1 every time (P=0.5), or it is possible that 0 has been tossed i times before and finally 1 (P=1-0.5^i); the more times you play the coin tossing game, the easier it is to have 0s for many times in the past. This is because there are consecutive 0s at the beginning. The more 0s appear, the smaller the probability of occurrence, and the more times the Bernoulli process needs to be tried. Therefore, the probability can be used to deduce the condition (how many times the game has been played, i.e. n=2^i) based on the result (the number of 0s appearing at the beginning, i.e. i). This is also easy to understand. For example, the probability of winning a lottery is 1/10,000, that is, it takes an average of 10,000 lottery tickets to win one prize. On the other hand, if someone wins a prize, he should buy 10,000 lottery tickets with a high probability);

However, due to the existence of randomness, the error is large, so the randomness is reduced by dividing the dataset into m parts, each part is counted separately, and finally the arithmetic average is taken to reduce the error;

process

Each element of the dataset is first mapped to a bit array, such as a 32-bit bit array. The value from 1 to k bits of this bit array is used as the bucket_index of the bucket (that is, which bucket), and the first index of 1 among the k+1 to 32 bits is placed in the bucket as a value, such as If there is already a value in the bucket, the bucket will save the largest value. After all the data set elements are mapped, the arithmetic average of the values ​​of all the buckets is taken. According to n=2^i, the cardinality in each bucket can be obtained, and then multiplied by m to get the cardinality of the entire dataset. The alpha at the front of the formula is the correction parameter;

For example, k=2, then m=2^k=4, that is, 4 buckets. The bit array mapped by an element in the dataset is [1,0,0,0,0,1,0,...]. The value corresponding to the first two digits [1,0] is 2, which is the second bucket. Take the array after the third digit [0,0,0,1,0,...]. It can be seen that the index of the first bit 1 is 3. Put 3 into bucket 2, and so on;
