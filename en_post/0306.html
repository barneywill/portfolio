After beeline connects to Spark thrift, the execution of use database sometimes gets stuck, and use database corresponds to setCurrentDatabase on the server side.

After investigation, it was found that Spark thrift was performing an insert operation at that time.

The corresponding methods in HiveClientImpl will execute withHiveState, and withHiveState is synchronized, so part of the code in the insert operation (such as loadPartition) and the use database operation will be executed synchronously. When the insert execution is very slow, all other operations will be stuck;

 

For details on the implementation principle in Spark thrift, see https://www.cnblogs.com/barneywill/p/10137672.html
