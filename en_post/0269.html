The SSH protocol uses encryption to secure the connection between a client and a server. All user authentication, commands, output, and file transfers are encrypted to protect against attacks in the network. 

 

Key types include rsa and dsa, see https://security.stackexchange.com/questions/5096/rsa-vs-dsa-for-ssh-authentication-keys for details

The security of the RSA algorithm is based on the fact that factorization of large integers is known to be "difficult", whereas DSA security is based on the discrete logarithm problem.

rsa is based on large number decomposition, and dsa is based on discrete logarithms;

RSA keys can go up to 4096 bits, where DSA has to be exactly 1024 bits (although OpenSSL allows for more.)

The rsa key supports up to 4096 bits in length, and the dsa key only supports 1024 bits in length;

1 Generate secret key, rsa or dsa

1.1 Command generation (Linux or mac)

$ ssh-keygen -t rsa -b 4096

A password will be entered during the creation process;

After the creation is completed, two secret key files will be created by default in the .ssh directory of the home directory, the public key (pub suffix) and the private key.

$ ls .ssh
id_rsa id_rsa.pub

 When logging in, the private key is saved by itself and the public key is placed on the server.

1.2 securecrt or xshell interface generation (Windows)

The place where securecrt creates the secret key is

Tools--Create Public Keys

2 Upload the public key

Upload the public key to the user's home directory of the server you want to log in to, and add the public key to authorized_keys.

cat .ssh/id_rsa.pub >> .ssh/authorized_keys
chmod 600 .ssh/authorized_keys

3 Log in with local private key

3.1 Log in with ssh command (Linux or mac)

$ ssh -i /path/id_rsa user@remote_ip

In addition, you can also modify the configuration file and configure the key, so that -i can be dispensed with.

#vi /etc/ssh/ssh_config

IdentityFile ~/.ssh/id_rsa

4.1 Root user ssh password-free login

2 copies

1) There is no password, but you can log in to the server. After logging in to the server one by one, nc receives the file.

# nc -l $receive_port |tar -zxvf -

native execution

# tar -zcvf - .ssh |nc $receive_ip $receive_port

2) Have the login account and password of the server and copy them one by one.

# scp .ssh/id_rsa.pub root@$server_ip:/root/.ssh

3 SSH login verification one by one

# ssh $server_ip

# scp .ssh/known_hosts $server_ip:/root/.ssh/

5 Troubleshooting

If you are still prompted to enter a password after configuring the certificate, you need to check the log on the server /var/logs/auth.log

If there are logs in it: User *** from *** not allowed because none of user's groups are listed in AllowGroups

View sshd configuration /etc/ssh/sshd_config

AllowGroups root ssh

Several methods: 1. Comment; 2. Add the user to the relevant group; 3. Add the user's group here;
