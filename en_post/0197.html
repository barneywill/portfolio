Deployment method: Docker+airflow+MySQL+LocalExecutor

Using airflow’s Docker image

https://hub.docker.com/r/puckel/docker-airflow

Start using the default SQLite+SequentialExecutor:

$ docker run -d -p 8080:8080 puckel/docker-airflow webserver

Copy airflow.cfg in the container and modify it

$ docker cp $container_id:/usr/local/airflow/airflow.cfg .

Try using custom airflow.cfg

-v /usr/local/airflow/airflow.cfg:/usr/local/airflow/airflow.cfg

Among them, modify sql_alchemy_conn to MySQL and modify executor = LocalExecutor

Found that SequentialExecutor is still used

[2019-02-28 19:37:16,170] {{__init__.py:51}} INFO - Using executor SequentialExecutor

View Dockerfile: Docker-airflow/Dockerfile

ENTRYPOINT ["/entrypoint.sh"]
CMD ["webserver"] # set default arg for entrypoint

It was found that the last script started was entrypoint.sh

View entrypoint.sh: Docker-airflow/script/entrypoint.sh

: "${AIRFLOW__CORE__EXECUTOR:=${EXECUTOR:-Sequential}Executor}"

...

if [ "$AIRFLOW__CORE__EXECUTOR" != "SequentialExecutor" ]; then

  AIRFLOW__CORE__SQL_ALCHEMY_CONN="postgresql+psycopg2://$POSTGRES_USER:$POSTGRES_PASSWORD@$POSTGRES_HOST:$POSTGRES_PORT/$POSTGRES_DB"

  AIRFLOW__CELERY__RESULT_BACKEND="db+postgresql://$POSTGRES_USER:$POSTGRES_PASSWORD@$POSTGRES_HOST:$POSTGRES_PORT/$POSTGRES_DB"

  wait_for_port "Postgres" "$POSTGRES_HOST" "$POSTGRES_PORT"

fi

...

case "$1" in

  webserver)

    airflow initdb

    if [ "$AIRFLOW__CORE__EXECUTOR" = "LocalExecutor" ]; then

      # With the "Local" executor it should all run in one container.

      airflow scheduler &

    fi

    exec airflow webserver

    ;;

1) Get the environment variable EXECUTOR (the value is Sequential, Local, etc.) to construct the environment variable AIRFLOW__CORE__EXECUTOR;
2) If AIRFLOW__CORE__EXECUTOR is not SequentialExecutor, wait for postgres (it is mandatory to rely on postgres here);
3) If the startup parameter is webserver and AIRFLOW__CORE__EXECUTOR=LocalExecutor, scheduler will be started automatically;

Due to Airflow’s automatic environment variable expansion, you can also set the env var AIRFLOW__CORE__* to temporarily overwrite airflow.cfg.

Since the environment variable has a higher priority than airflow.cfg, even if the executor=LocalExecutor in airflow.cfg is modified, the SequentialExecutor is actually used; copy the entrypoint.sh in the container and modify it.

$ docker cp $container_id:/entrypoint.sh .

Comment out the following lines

#if [ "$AIRFLOW__CORE__EXECUTOR" != "SequentialExecutor" ]; then

#  AIRFLOW__CORE__SQL_ALCHEMY_CONN="postgresql+psycopg2://$POSTGRES_USER:$POSTGRES_PASSWORD@$POSTGRES_HOST:$POSTGRES_PORT/$POSTGRES_DB"

#  AIRFLOW__CELERY__RESULT_BACKEND="db+postgresql://$POSTGRES_USER:$POSTGRES_PASSWORD@$POSTGRES_HOST:$POSTGRES_PORT/$POSTGRES_DB"

#  wait_for_port "Postgres" "$POSTGRES_HOST" "$POSTGRES_PORT"

#fi

Start command

$ docker run -d -p 8080:8080 -e EXECUTOR=Local -v /usr/local/airflow/airflow.cfg:/usr/local/airflow/airflow.cfg -v /usr/local/airflow/entrypoint.sh:/entrypoint.sh -v /usr/local/airflow/dags:/usr/local/airflow/dags -v /usr/local/airflow/logs:/usr/local/airflow/logs puckel/docker-airflow webserver

 

Although it is a single point, it can be made highly available for use in production environments with mesos+HDFS nfs;
