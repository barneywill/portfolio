CM deploys Kafka

📅 February 26, 2019
📖 1 min read
👁️ 939 views

1 Download Kafka parcel

http://archive.cloudera.com/kafka/parcels/latest/
KAFKA-3.1.1-1.3.1.1.p0.2-el7.parcel
KAFKA-3.1.1-1.3.1.1.p0.2-el7.parcel.sha1

# mv KAFKA-3.1.1-1.3.1.1.p0.2-el7.parcel.sha1 KAFKA-3.1.1-1.3.1.1.p0.2-el7.parcel.sha
# cp KAFKA-3.1.1-1.3.1.1.p0.2-el7.parcel* /opt/cloudera/parcel-repo/

2 Restart Cloudera Manager

Go to the menu ‘Host’ -> ‘Parcel’ 

Click on ‘Assign’ 

Click ‘Activate’

wait

3 Add services

 

An OOM error may be reported when starting Kafka. Check the logs to find out.

export KAFKA_HEAP_OPTS=-Xmx50M

This is too small. Set BROKER_HEAP_SIZE first in control.sh, and then set KAFKA_HEAP_OPTS

/opt/cloudera-manager/cm-5.16.1/run/cloudera-scm-agent/process/349-kafka-KAFKA_BROKER/scripts/control.sh

Directly modify the startup script

# vi /opt/cloudera/parcels/KAFKA-3.1.0-1.3.1.0.p0.35/lib/kafka/bin/kafka-server-start.sh
...
export KAFKA_HEAP_OPTS="-Xmx1G - Xms1G"
exec $base_dir/kafka-run-class.sh $EXTRA_ARGS com.cloudera.kafka.wrap.Kafka "$@"

Synchronize to all servers and then try to start Kafka again

If you want to modify ZooKeeper Chroot, it must start with /, such as /Kafka

 

Deployment successful

The deployed Kafka version is kafka_2.11-1.0.1-Kafka-3.1.1.jar, which corresponds to the official version kafka_2.11-1.0.1
