 For details on HDFS code analysis, see https://www.cnblogs.com/barneywill/p/10114504.html       

Note:

int maxNodesPerRack = (totalNumOfReplicas-1)/numOfRacks + 2;

Result: maxNodesPerRack = (2-1)/5+2 = 2;

    if (maxNodesPerRack == totalNumOfReplicas) {

      maxNodesPerRack--;

    }

Result: maxNodesPerRack = 1;

Due to the excessive number of racks, only one DataNode can be allocated to a rack. Combined with the current HDFS rack structure, only one rack is available, so there is only 1 copy.

Problem summary

In the final analysis, all problems are caused by the HDFS rack configuration. Some servers are configured with rack information, and some servers are not configured with rack information, resulting in a particularly large number of racks, and the servers in the racks are unevenly distributed. According to the HDFS allocation strategy, it can be calculated that in this case, a rack can only be allocated a maximum of one D Atanode, at the same time, the remaining space of datanodes on a large number of racks is 0, so many files only have one copy, which creates a single point. Once a DataNode node status is abnormal, it may cause a large number of files to be unavailable, which will lead to a series of other problems, such as the HBase above The region has been offline for a long time.

The problem was found in Hive, the direct cause was HBase, and the root cause was HDFS, which was essentially due to improper rack configuration;
