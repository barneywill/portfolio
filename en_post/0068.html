Timezone Offset When Impala Reads parquet Timestamp Fields

📅 June 08, 2020
📖 1 min read
👁️ 1301 views

The time field in the parquet file is read normally in Hive and spark-SQL, but will be offset by 8 hours (less) when read in Impala. The test results are as follows:

1. Do not modify the Impala configuration

1 Write parquet from spark or Hive

  • spark and Hive read normally
  • Impala reads an offset of 8 hours (less) and requires manual offset from_unixtime(unix_timestamp(time) + 28800)

2. Modify Impala configuration

use_local_tz_for_unix_timestamp_conversions=true

convert_legacy_hive_parquet_utc_timestamps=true

1 Write parquet from spark or Hive

  • spark and Hive read normally
  • Impala reads normally

2 Writing to parquet by Impala

  • spark and Hive read offset 8 hours (more)
  • Impala reads normally

 

Reference: https://docs.cloudera.com/documentation/enterprise/latest/topics/Impala_timezone.html
