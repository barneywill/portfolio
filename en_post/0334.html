Why does a Broadcast timeout error appear when adding a limit to a large table subquery in Spark?

📅 December 12, 2018
📖 3 min read
👁️ 7139 views

When two tables need to be joined, if one is a large table and the other is a small table, the normal map-reduce process requires shuffle, which will cause the large table data to be transmitted over the network between nodes. A common optimization method is to read the small table into memory and broadcast it to the large table for processing to avoid shuffle+reduce;

It is called mapjoin (map-side join) in Hive and is configured as Hive.auto.convert.join

Called BroadcastHashJoin (broadcast hash join) in Spark

Spark SQL uses broadcast join (aka broadcast hash join) instead of hash join to optimize join queries when the size of one side data is below spark.sql.autoBroadcastJoinThreshold.

Broadcast join can be very efficient for joins between a large table (fact) with relatively small tables (dimensions) that could then be used to perform a star-schema join. It can avoid sending all data of the large table over the network.

There are several ways to trigger:

1) SQL hint (supported from Spark 2.3 version)

SELECT /*+ MAPJOIN(b) */ ...

SELECT /*+ BROADCASTJOIN(b) */ ...

SELECT /*+ BROADCAST(b) */ ...

2）broadcast function：DataFrame.broadcast

testTable3= testTable1.join(broadcast(testTable2), Seq("id"), "right_outer")

3) Automatic optimization

org.apache.spark.sql.execution.SparkStrategies.JoinSelection

    private def canBroadcast(plan: LogicalPlan): Boolean = {
      plan.statistics.isBroadcastable ||

        (plan.statistics.sizeInBytes >= 0 &&

          plan.statistics.sizeInBytes <= conf.autoBroadcastJoinThreshold)

    }

BroadcastExchange The execution process is

org.apache.spark.sql.execution.exchange.BroadcastExchangeExec

  override protected[sql] def doExecuteBroadcast[T](): broadcast.Broadcast[T] = {

    ThreadUtils.awaitResultInForkJoinSafely(relationFuture, timeout)

      .asInstanceOf[broadcast.Broadcast[T]]

  }

Where timeout refers to Spark.SQL.broadcastTimeout, the default is 300s

  private lazy val relationFuture: Future[broadcast.Broadcast[Any]] = {

    // broadcastFuture is used in "doExecute". Therefore we can get the execution id correctly here.

    val executionId = sparkContext.getLocalProperty(SQLExecution.EXECUTION_ID_KEY)

    Future {

      // This will run in another thread. Set the execution id so that we can connect these jobs

      // with the correct execution.

      SQLExecution.withExecutionId(sparkContext, executionId) {

        try {

          val beforeCollect = System.nanoTime()

          // Note that we use .executeCollect() because we don't want to convert data to Scala types

          val input: Array[InternalRow] = child.executeCollect()

          if (input.length >= 512000000) {

            throw new SparkException(

              s"Cannot broadcast the table with more than 512 millions rows: ${input.length} rows")

          }

          val beforeBuild = System.nanoTime()

          longMetric("collectTime") += (beforeBuild - beforeCollect) / 1000000

          val dataSize = input.map(_.asInstanceOf[UnsafeRow].getSizeInBytes.toLong).sum

          longMetric("dataSize") += dataSize

          if (dataSize >= (8L << 30)) {

            throw new SparkException(

              s"Cannot broadcast the table that is larger than 8GB: ${dataSize >> 30} GB")

          }

 

          // Construct and broadcast the relation.

          val relation = mode.transform(input)

          val beforeBroadcast = System.nanoTime()

          longMetric("buildTime") += (beforeBroadcast - beforeBuild) / 1000000

 

          val broadcasted = sparkContext.broadcast(relation)

          longMetric("broadcastTime") += (System.nanoTime() - beforeBroadcast) / 1000000

 

          SQLMetrics.postDriverMetricUpdates(sparkContext, executionId, metrics.values.toSeq)

          broadcasted

The execution process of broadcasting a table is to first calculate and then collect, and then broadcast it through SparkContext, and the execution process is asynchronously executed by threads, and the timeout is Spark.SQL.broadcastTimeout;
