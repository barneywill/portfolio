Hive reads and writes Elasticsearch data through external tables

📅 January 21, 2019
📖 1 min read
👁️ 3732 views

Hive reads and writes Elasticsearch data through external tables, which is similar to reading and writing HBase data. The difference is that you need to download Elasticsearch-hadoop-Hive-6.6.2.jar, and then use the EsStorageHandler in it;

Connect the massive data storage and deep processing power of Hadoop with the real-time search and analytics of Elasticsearch. The Elasticsearch-Hadoop (ES-Hadoop) connector lets you get quick insight from your big data and makes working in the Hadoop ecosystem even better.

Official: https://www.elastic.co/products/hadoop
Download: https://www.elastic.co/downloads/hadoop

 

The latest version currently is 6.6.2

# wget https://artifacts.elastic.co/downloads/elasticsearch-hadoop/elasticsearch-hadoop-6.6.2.zip
# unzip elasticsearch-hadoop-6.6.2.zip

Use Elasticsearch-hadoop-6.6.2/dist/Elasticsearch-hadoop-Hive-6.6.2.jar

add jar /path/to/elasticsearch-hadoop-hive-6.6.2.jar;

CREATE EXTERNAL TABLE hive_elasticsearch_table (
id string,
name string,
desc string
)
STORED BY 'org.elasticsearch.hadoop.hive.EsStorageHandler'
TBLPROPERTIES(
'es.nodes' = '$es_server1:9200,$es_server2:9200',
'es.index.auto.create' = 'false',
'es.resource' = 'testdoc/testtype',
'es.read.metadata' = 'true',
'es.mapping.names' = 'id:_metadata._id, name:name, desc:desc');

 The main thing is to configure Elasticsearch.nodes, Elasticsearch.resource and Elasticsearch.mapping.names. One is the Elasticsearch server address, the other is the index name and type name, and the other is the one-to-one mapping of Hive fields and Elasticsearch fields. Then you can read and write Elasticsearch data in Hive:

select * from hive_elasticsearch_table limit 10;
insert into table hive_elasticsearch_table select '2', 'testname', 'testdesc';

But it turns out that the ID has been hashed.

+------------------------------+--------------------------------+--------------------------------+--+
| hive_elasticsearch_table.id | hive_elasticsearch_table.name | hive_elasticsearch_table.desc |
+------------------------------+--------------------------------+--------------------------------+--+
| 6mpoc2gBohlnD12tvBoF | testname | testdesc |
+------------------------------+--------------------------------+--------------------------------+--+

You also need to add another Elasticsearch.mapping.id to define which field is the id of the document

CREATE EXTERNAL TABLE hive_elasticsearch_table (
id string,
name string,
desc string
)
STORED BY 'org.elasticsearch.hadoop.hive.EsStorageHandler'
TBLPROPERTIES(
'es.nodes' = '$es_server1:9200,$es_server2:9200',
'es.index.auto.create' = 'false',
'es.resource' = 'testdoc/testtype',
'es.read.metadata' = 'true',
'es.mapping.id' = 'id',
'es.mapping.names' = 'id:_metadata._id, name:name, desc:desc');

It's normal this time

+------------------------------+--------------------------------+--------------------------------+--+
| hive_elasticsearch_table.id | hive_elasticsearch_table.name | hive_elasticsearch_table.desc |
+------------------------------+--------------------------------+--------------------------------+--+
| 6mpoc2gBohlnD12tvBoF | testname | testdesc |
| 4 | hello | world |
+------------------------------+--------------------------------+--------------------------------+--+

 

For details on field type mapping, see: https://www.elastic.co/guide/en/Elasticsearch/hadoop/current/mapping.html
