Session mechanism

JSESSIONID is the identifier of the Session. When the client requests the server, the server will check whether a Session has been created for the client, that is, whether the header in the client's request has Cookie: JSESSIONID=.... If the client request contains JSESSIONID, then the server can use JSESSI ONID finds the corresponding Session; if not, the server thinks that the client is visiting for the first time and will add a header to the response, namely Set-Cookie:JSESSIONID=…. When the client receives the response, the cookie will be set, and subsequent requests will carry the cookie to ensure the consistency of the session;

2 Distributed Session Implementation

2.1 Pseudo-distributed Session

2.1.1 nginx ip_hash

Distribute requests to different servers based on the client's IP;

The configuration is as follows:

upstream my_upstream {

                ip_hash;

                server 10.20.35.11:8001;
                server 10.20.35.11:8002;
 }

2.1.2 nginx sticky

https://bitbucket.org/nginx-goodies/nginx-sticky-module-ng/overview

After downloading, recompile Nginx through --add-module;

The configuration is as follows:

upstream my_upstream{
　　　　sticky;
　　　　server 10.20.35.11:8001;
　　　　server 10.20.35.11:8002;
}

Implementation principle:

Sticky is a module of Nginx. It is an Nginx load balancing solution based on cookies. By distributing and identifying cookies, the same client's requests fall on the same server. The default identification name is route.
1 The client initiates an access request for the first time. After Nginx receives it, it finds that there is no cookie in the request header, and then distributes the request to the back-end server in a polling manner.
2. The backend server processes the request and returns the response data to Nginx.
3 At this time, Nginx generates a cookie with route and returns it to the client. The value of route corresponds to the back-end server. It may be plain text or hash values ​​such as md5 and sha1.
4 The client receives the request and saves the cookie with route.
5 When the client sends a request next time, it will bring the route, and Nginx will forward it to the corresponding back-end server based on the route value in the received cookie.

 

2.2 True Distributed Session

Backend implementation:

1 Inherit HttpSessionWrapper, such as DistributeHttpSessionWrapper, override getAttributeNames, getAttribute, setAttribute and other methods, and instead read and write session attributes in a public place, such as DB, Memcached, Redis, etc.;

javax.servlet.http.HttpSession

2 Inherit HttpServletRequestWrapper, such as DistributeHttpServletRequestWrapper, override the getSession method and return DistributeHttpSessionWrapper instead;

javax.servlet.http.HttpServletRequestWrapper

2 Inherit Filter, such as DistributeSessionFilter, override the doFilter method, and replace HttpServletRequest with DistributeHttpServletRequestWrapper in the call chain;

javax.servlet.Filter
