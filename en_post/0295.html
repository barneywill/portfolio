Hive 1 - Code flow of Hive SQL execution process

📅 December 27, 2018
📖 14 min read
👁️ 3784 views

hive 2.1

 

There are two ways for Hive to execute SQL:

  • Execute Hive commands, which are subdivided into Hive - e, Hive - f, and Hive interactive;
  • Execute the beeline command, and beeline will connect to the remote thrift server;

Let’s look at how SQL is executed in these scenarios:

1 Hive command

Start command

Start Hive client command

$HIVE_HOME/bin/hive

Equivalent to

$HIVE_HOME/bin/hive --service cli

will call

$HIVE_HOME/bin/ext/cli.sh

The actual startup class is: org.apache.hadoop.Hive.cli.CliDriver

CliDriver.main will call run, and run will call executeDriver, which corresponds to the three situations mentioned above:

  • One is Hive-e to execute SQL. At this time, ss.execString is not empty, and the process exits after execution;
  • One is Hive - f to execute the SQL file. At this time, ss.fileName is not empty, and the process exits after execution;
  • One is Hive interactive execution of SQL. At this time, reader.readLine will be continuously read, and then the execution will be lost and the result will be output;

The above three situations will eventually call processLine, and processLine will call processLocalCmd. In processLocalCmd, Driver.run will first be called to execute the SQL. After execution, Driver.getResults will be called to output the results. These are also the two most important interfaces of Driver. We will look at Driver implementation later;

2 beeline command

Beeline needs to connect to the Hive thrift server. Let's first see how to start the Hive thrift server:

hive thrift server

Start Hive thrift server command

$HIVE_HOME/bin/hiveserver2

$HIVE_HOME/bin/hive --service hiveserver2

$HIVE_HOME/bin/ext/hiveserver2.sh

Operation is an abstract class,

  • run will call the abstract method runInternal
  • getNextRowSet will call the abstract method getNextRowSet
